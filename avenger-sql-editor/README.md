# avenger-sql-editor

A lightweight desktop editor of avenger-sql projects. A project of [avenger-sql-project](../avenger-sql-project/README.md) opens with its files by role, each open file in a tab, and a gallery of its charts, and the result of each chart script shows as a chart, or as a table whose chart columns show the chart of each row. The editor embeds a sample project, which it opens when it starts: nine sample tables, three of them geographic, and a chart script for each example of the gallery, maps among them.

## Run

```bash
cargo run --release -p avenger-sql-editor
```

The editor opens the sample project. `--project <PATH>` opens the project of a directory, or of a path under it, in its place, and a file of the project in a tab, such as `--project avenger-sql-project/tests/projects/vega/charts/origins.sql`. `--open <PATH>` opens a file of the project in a tab by its path relative to the project's root, such as `--open charts/07-maps/01-earthquakes-by-depth.sql` of the sample project. A chart that opens runs. `--screenshot <PNG>` saves the window to a PNG once the project, its charts, and the gallery's thumbnails in view finish, and then exits. Before the screenshot, `--cursor <INDEX>` puts the cursor before the character at the index, each `--press <KEYS>` presses keys in order, such as `alt+Space` to open the completions or `F12` to go to the definition, and `--hover` holds the pointer over the character after the cursor. `--theme <system|light|dark>` sets the theme in place of the one that the editor remembers, and a run that saves a screenshot leaves the remembered theme as it was.

## Run in a browser

The editor also builds for the web with wasm-pack, from the repository root:

```bash
wasm-pack build avenger-sql-editor --target web --release --out-dir web/pkg
```

```bash
python3 -m http.server 8776 -d avenger-sql-editor/web
```

Then open `http://localhost:8776`. DataFusion compresses Arrow IPC with zstd, which compiles C, and Apple's clang has no wasm32 target, so on macOS set `CC_wasm32_unknown_unknown` and `AR_wasm32_unknown_unknown` to the `clang` and `llvm-ar` of Homebrew's LLVM, such as `/opt/homebrew/opt/llvm/bin/clang`. In the browser, the editor opens the sample project and its gallery, as the desktop editor does, and opens no projects of the user's. A chart or a chart cell runs on the page's one thread, so the page waits while it runs.

The data scripts of both builds read CSV, JSON, Arrow IPC, and Parquet files, and CSV and JSON files compressed with gzip, bzip2, xz, or zstd, through avenger-sql's `parquet` and `compression` features. The desktop editor also reads Avro files, through the `avro` feature, which does not build for the web.

## The sample project

The editor embeds the files of [`samples/`](samples/README.md), and the three Arrow IPC streams of the geographic samples from `avenger-guides-geo/examples/data` at `data/files/geo/`, as its `build.rs` lists them, and opens them through avenger-sql-project's embedded file source, `FileSource::embedded`, in the desktop editor and in the browser. Its data script `data/samples.sql` loads the sample tables into the schema `samples`, such as `samples.penguins`, and each chart script under `charts/` is an example. [`samples/data/files/README.md`](samples/data/files/README.md) gives the source and the terms of each file.

The sample project is read-only. Its tabs take edits, and Run runs a chart's text as it is in the tab, but Save is off, with a hover that says that a sample can't be saved. **Project** in the toolbar opens a project of your own in its place, or makes one, and "Sample project" opens the samples again. The tables of the samples belong to the sample project: a project of your own reads its own tables, and not `samples`.

## The window

- **The sidebar**, on the left, lists the project's files by role: the data scripts, each with the tables and views that it registered and their columns, and a warning sign with its errors when it did not load, the chart scripts by folder, each with its own tables of files and their columns, once the chart has run and the loader has read its files, the stylesheets, and the modules with their module paths. Clicking a script, a stylesheet, or a module opens it in a tab. Clicking a column or a function, or "Insert" under a table, inserts its name at the cursor. Under the files, the sidebar lists the functions that avenger-sql adds, by their families in its library: the marks, the compositions, the constructors, and the transforms.
- **Tabs** above the editor hold the open files, each with its own text, cursor, and undo history, and a dot while its text differs from its file. × closes a tab, and its changes that are not saved.
- **The editor** reads the project's analysis of the tab's file, a `Document` of avenger-sql-language in the language's `Project`, with the tables of the project. It colors the tokens by the document's highlights, which the analysis refines, so that a mark, a column, and a table each take their own color, and it underlines each error that the document reports, with the project's errors, such as a read of a table whose data script did not load, and the load's errors, such as a URI that matches no file. Option+Space (Ctrl+Space on other platforms) opens the document's completions at the cursor, which the typed name filters, with the items of each kind under a heading, such as Columns or Marks, and the selected item's documentation beside the list: the arrows move the selection, Enter or Tab inserts it, and Escape closes the list. Hover over a name to read its documentation, over the name of an argument to read its parameter, or over an underlined error to read its message and help. ⌘. (Ctrl+.) on an error lists its fixes, and Enter applies the selected one. While the cursor is on a name, its definition and each use of it show on a faint background, and F12 or ⌘-click (Ctrl-click) on a name selects its definition: on a table of a chart, the statement of the data script that creates it, in its tab, and on `IMPORT MODULE`, the module. ⌘↵ (Ctrl+Enter on other platforms) or Run runs the chart of the tab. ⌘/ (Ctrl+/) comments the lines of the selection out with `--`, or back in when they all are comments. Format, or ⇧⌥F (Shift+Alt+F), formats the script in the style of avenger-sql's `STYLE.md`, unless it has a syntax error. Enter starts a new line at its depth by the style, and typing a line's first token, such as `)`, `|>`, or `GROUP `, moves the line to its depth. Tab re-indents the line or the lines of the selection, moves a cursor in the indentation to the first word, and otherwise opens the completions, and Shift+Tab does nothing. A chart that runs for more than 200 ms can be canceled from the status bar. The Light, Dark, and System buttons of the toolbar set the theme, which the editor remembers across launches, and System follows the system's appearance. In either theme, each chart's background is the color of the panels, so that a chart and the panel around it are one surface, and the charts draw for a dark surface in the dark theme.
- **Gallery**, the view of the result pane when a project opens, shows a card for each chart script of the project, by section, with a thumbnail of its chart, and the number of its charts for a result of several. A card's section is the folder of its chart under `charts/`, its title is the file stem with a space for each `-` and a capital first letter, and its description is the comment block at the start of the chart's text, as [`samples/README.md`](samples/README.md) describes. A leading number and `-` of a folder or a file, as in `01-penguins` or `01-body-mass-vs-flipper-length.sql`, orders it and is not part of its heading or title, and the cards of a section are in the order of their paths. A card runs its chart the first time it comes into view, four at a time, and keeps its result until the chart is saved or a load changes a table that it reads. Hover over a card to read its description. Click a card to open its chart in a tab and run it. The search box keeps the charts whose title, description, section, or text holds the text.
- **Result** shows the result of the shown tab. A result of one row and one column that holds a chart shows as an interactive chart that fills the pane. Every other result shows as a table. Each chart column of the table shows the chart of each visible row as a static image.
  - A map with `tiles` fetches the tiles of each view as it comes into view. The desktop editor fetches them with its own User-Agent and keeps them on disk in the folder of its settings, in `images`, as OpenStreetMap's tile usage policy asks, and the browser fetches them with its own `fetch`. The static images of the table and the thumbnails of the gallery draw their tiles too, and each draws again as its tiles arrive.
  - Drag the edge of a column header to change the width of a column, and drag the bottom edge of a row to change the height of every row. The charts draw at the new size in each frame of the drag, and so does a single chart while the window resizes.
  - Hover over a chart cell and click the expand button at its top-right corner, or double-click the cell, to open its chart in the whole result pane. A bar above it names the row by its other columns. **Back**, or Escape while neither the pointer nor the keyboard is on the chart, returns to the table where it was. A new result closes the chart.
  - Turn on **Interactive charts**, above the table, to pan, zoom, and select in every visible chart of the table. It is off when the editor starts, so that the wheel scrolls the table over the charts. A chart that scrolls out of view, or a result that replaces the table, drops its pans and zooms.
- **Lifted SQL** shows the chart's query as the staged query that its mark calls with statistics plan, as `avenger_sql::lift` prints it, with the text that it wrote highlighted, and **Plan** shows the optimized logical plan of the last result.

While a chart has an error, the result pane keeps the last result that ran.

## Projects

A project is a directory whose root holds `avenger.toml`, with data scripts that load its tables, chart scripts, modules, and stylesheets. **Project** in the toolbar opens one: "Open project…" picks its directory, and "New project…" picks a directory, writes the smallest manifest there, named after the directory, unless the directory has a manifest, and opens it. An error of the manifest, or a directory outside any project, shows in the status bar. The project loads in the background: its data scripts load into a session of their own, and every data script, chart script, and module is analyzed together, as avenger-sql-language's `Project` analyzes them, with the tables of the files that the load read.

- **Saving**: ⌘S (Ctrl+S), or Save, writes the active tab to its file. A saved data script loads again, with the scripts downstream of it, and the open chart tabs and the gallery's cards that read a table that changed run again, and so do those that import a module, whose functions can read tables that the chart doesn't name. A saved module loads the whole project again. A chart runs when its tab opens, when it is saved, and on Run, against the project's tables, and its result shows in the result pane, which shows the last result of each tab as the tab shows. A saved chart's card runs again. A chart that reads a table of a data script that did not load has the error that names the script. A run waits for a load that has not ended, so a chart never reads a project that is partly loaded. A save of a file that another program changed since the editor read it fails, and keeps the other program's text. Before another project opens, and before the window closes, a dialog asks what becomes of the edits that are not saved: Save all saves them, Discard drops them, and Cancel keeps the open project. The sample project's dialog has no Save all.
- **Stylesheets**: every chart of the project, in the result pane, in the cells of a table, and in the gallery, takes the cascade of the base stylesheet, `std:base.css`, and after it the project's entry stylesheet, `styles/main.css` unless the manifest names another, as an author stylesheet, with the imports of the entry stylesheet in its cascade order. Both read the same `env()` values, such as the panel's `background`, in the light theme and the dark one. A project without an entry stylesheet has the base stylesheet alone. A saved stylesheet loads the stylesheets again, and the charts restyle without running their scripts again: the interactive charts keep their pans, zooms, and selections. A stylesheet's tab colors its text by its tokens, and underlines the errors and warnings of the last load of the stylesheets, its own and those of its imports, such as an unknown attribute or an import that does not load, with the message and help of each on hover. A stylesheet that the entry stylesheet does not reach through its imports has a warning on its first line, since it styles no chart. While a stylesheet's tab is active, the result pane keeps the result of the tab before it, so the chart shows each save of the stylesheet. Completion, Format, ⌘/, the style's indentation, and definitions are for SQL only.

- **Add file**: "Add file…" in **Project** picks data files and adds them to the project, and so does dropping files on the window. A file under the project's root stays where it is, and a file outside it is copied into `data/files/`, with `-2`, `-3`, and so on after its name when a file there has the name, so that no file is overwritten. Each file gets a `CREATE EXTERNAL TABLE` statement in the style of avenger-sql's formatter, with the format from its extension, `.csv`, `.json`, `.parquet`, `.avro`, or `.arrow`, and `compression` for a CSV or JSON file that ends with `.gz`, `.bz2`, `.xz`, or `.zst`. The table name is the name of the file before its extensions, in lowercase, with `_` for each character that is not a letter, a digit, or `_`, and with a number after it when a data script of the project defines the name. A file with another extension is not added, and the status bar says so. The statements go at the end of the active tab's data script, or else of the first data script by path, or else of a new `data/tables.sql`, and the script opens in a tab. When the active tab is a chart script, each file gets a `CREATE TEMP EXTERNAL TABLE` statement in the chart, before its query and after its other statements of files, with a name that no table of the project and no table of the chart has, so the table is the chart's own, which no other chart sees, and the saved chart runs again. A script without edits that are not saved is saved and loads, so its tables show in the sidebar. A script whose tab holds edits that are not saved takes the statements in its tab, and loads when it is saved. The sample project takes no files, and Add file is off for it, with a hover that says so.
- **Files that change on disk**: the editor watches the project's directory. When a file that a data script reads changes, is removed, or is created where a URI of a script names it, such as in a directory or under a pattern of the URI, the script loads again, with the scripts downstream of it, as after a save, and the charts and the gallery's cards that read a table that changed run again. A chart whose own tables of files read such a file, in its last run, drops those tables, and its tab and its card run again. A burst of changes loads once, after 200 ms without a change, and each script loads once for the files of the burst. Hidden files, and the files under hidden directories, are not watched, and neither is the manifest. A script, a module, or a stylesheet that another program changes is read again, and loads, runs, or restyles as after a save, unless its tab holds edits that are not saved: the tab keeps them, and its save fails, since it would lose the other program's change. The files of Add file copy in the background, and their statements go into the script when the copies end.

Run is off in the tab of a data script, which loads when it is saved.

## Limits

- A stylesheet's errors show only after it loads again, when it is saved or changes on disk.
- The browser build adds no files, and does not watch them.
- No Delta tables, no remote files, and no saved sessions yet.
- Charts in table cells have no tooltips while **Interactive charts** is off.
