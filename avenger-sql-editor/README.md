# avenger-sql-editor

A lightweight desktop editor of avenger-sql queries. CSV and Parquet files become tables of a DataFusion session with the functions of avenger-sql, and the result of each query shows as a chart, or as a table whose chart columns show the chart of each row. The editor holds nine sample tables, three of them geographic, and a gallery of example queries over them, maps among them.

## Run

```bash
cargo run --release -p avenger-sql-editor
```

Each path argument is a CSV or Parquet file to open as a table. `--query <FILE>` opens a query and runs it once the files are open. `--project <PATH>` opens the project of a directory, or of a path under it, in place of the files, and a file of the project in a tab, such as `--project avenger-sql-project/tests/projects/vega/charts/origins.sql`. `--screenshot <PNG>` saves the window to a PNG once the query and its charts finish, and then exits. Before the screenshot, `--cursor <INDEX>` puts the cursor before the character at the index, each `--press <KEYS>` presses keys in order, such as `alt+Space` to open the completions or `F12` to go to the definition, and `--hover` holds the pointer over the character after the cursor. `--theme <system|light|dark>` sets the theme in place of the one that the editor remembers, and a run that saves a screenshot leaves the remembered theme as it was.

## Run in a browser

The editor also builds for the web with wasm-pack, from the repository root:

```bash
wasm-pack build avenger-sql-editor --target web --release --out-dir web/pkg
```

```bash
python3 -m http.server 8776 -d avenger-sql-editor/web
```

Then open `http://localhost:8776`. DataFusion compresses Arrow IPC with zstd, which compiles C, and Apple's clang has no wasm32 target, so on macOS set `CC_wasm32_unknown_unknown` and `AR_wasm32_unknown_unknown` to the `clang` and `llvm-ar` of Homebrew's LLVM, such as `/opt/homebrew/opt/llvm/bin/clang`. In the browser, the editor reads the sample tables only, opens no projects, and a query or a chart cell runs on the page's one thread, so the page waits while it runs.

## The window

- **Data**, on the left, lists the tables of your files, the sample tables, each with its columns, and the functions that avenger-sql adds, by their families in its library: the marks, the compositions, the constructors, and the transforms. "Add" opens CSV and Parquet files, and so does dropping files on the window. A table takes its name from its file: the file stem in lowercase, with `_` for each character that is not an ASCII letter, a digit, or `_`. Clicking a column or a function, or "Insert" under a table, inserts its name at the cursor. The sample tables are in the schema `samples`, such as `samples.penguins`, so a file named `penguins.csv` is the table `penguins` beside them. [`samples/README.md`](samples/README.md) gives the source and the terms of each.
- **The editor** reads a `Document` of avenger-sql-language for the query, over the tables of the session. It colors the tokens by the document's highlights, which the analysis refines, so that a mark, a column, and a table each take their own color, and it underlines each error that the document reports. Option+Space (Ctrl+Space on other platforms) opens the document's completions at the cursor, which the typed name filters, with the items of each kind under a heading, such as Columns or Marks, and the selected item's documentation beside the list: the arrows move the selection, Enter or Tab inserts it, and Escape closes the list. Hover over a name to read its documentation, over the name of an argument to read its parameter, or over an underlined error to read its message and help. ⌘. (Ctrl+.) on an error lists its fixes, and Enter applies the selected one. While the cursor is on a name, its definition and each use of it show on a faint background, and F12 or ⌘-click (Ctrl-click) on a name selects its definition. ⌘↵ (Ctrl+Enter on other platforms) or Run runs the query. ⌘/ (Ctrl+/) comments the lines of the selection out with `--`, or back in when they all are comments. Format, or ⇧⌥F (Shift+Alt+F), formats the query in the style of avenger-sql's `STYLE.md`, unless it has a syntax error. Enter starts a new line at its depth by the style, and typing a line's first token, such as `)`, `|>`, or `GROUP `, moves the line to its depth. Tab re-indents the line or the lines of the selection, moves a cursor in the indentation to the first word, and otherwise opens the completions, and Shift+Tab does nothing. A query that runs for more than 200 ms can be canceled from the status bar. The Light, Dark, and System buttons of the toolbar set the theme, which the editor remembers across launches, and System follows the system's appearance. In either theme, each chart's background is the color of the panels, so that a chart and the panel around it are one surface, and the charts draw for a dark surface in the dark theme.
- **Result** shows a result of one row and one column that holds a chart as an interactive chart that fills the pane. It shows every other result as a table. Each chart column of the table shows the chart of each visible row as a static image.
  - A map with `tiles` fetches the tiles of each view as it comes into view. The desktop editor fetches them with its own User-Agent and keeps them on disk in the folder of its settings, in `images`, as OpenStreetMap's tile usage policy asks, and the browser fetches them with its own `fetch`. The static images of the table and the thumbnails of the examples draw their tiles too, and each draws again as its tiles arrive.
  - Drag the edge of a column header to change the width of a column, and drag the bottom edge of a row to change the height of every row. The charts draw at the new size in each frame of the drag, and so does a single chart while the window resizes.
  - Hover over a chart cell and click the expand button at its top-right corner, or double-click the cell, to open its chart in the whole result pane. A bar above it names the row by its other columns. **Back**, or Escape while neither the pointer nor the keyboard is on the chart, returns to the table where it was. A new result closes the chart.
  - Turn on **Interactive charts**, above the table, to pan, zoom, and select in every visible chart of the table. It is off when the editor starts, so that the wheel scrolls the table over the charts. A chart that scrolls out of view, or a result that replaces the table, drops its pans and zooms.
- **Examples**, the view of the result pane when the editor starts, shows a card for each example query of [`examples.md`](examples.md), by section, with a thumbnail of its chart, and the number of its charts for a result of several. A card runs its query the first time it comes into view, four at a time, and keeps its result while the editor runs. Hover over a card to read what its chart shows. Click a card to put its query in the editor, under its title and description as comments, and run it. ⌘Z (Ctrl+Z) in the editor brings back the text before it. The search box keeps the examples whose title, description, section, or query holds the text.
- **Lifted SQL** shows the query as the staged query that its mark calls with statistics plan, as `avenger_sql::lift` prints it, with the text that it wrote highlighted, and **Plan** shows the optimized logical plan of the last result.

While a query has an error, the result pane keeps the last result that ran.

## Projects

A project of [avenger-sql-project](../avenger-sql-project/README.md) is a directory whose root holds `avenger.toml`, with data scripts that load its tables, chart scripts, modules, and stylesheets. **Project** in the toolbar opens one: "Open project…" picks its directory, and "New project…" picks a directory, writes the smallest manifest there, named after the directory, unless the directory has a manifest, and opens it. An error of the manifest, or a directory outside any project, shows in the status bar. The project loads in the background: its data scripts load into a session of their own, which has no sample tables, and every data script, chart script, and module is analyzed together, as avenger-sql-language's `Project` analyzes them, with the tables of the files that the load read.

- **The sidebar** lists the project's files by role in place of the files and the samples: the data scripts, each with the tables and views that it registered and their columns, and a warning sign with its errors when it did not load, the chart scripts by folder, the stylesheets, and the modules with their module paths. Clicking a script, a stylesheet, or a module opens it in a tab, and clicking a column, or "Insert" under a table, inserts its name at the cursor, as in a query.
- **Tabs** above the editor hold the open files, each with its own text, cursor, and undo history, and a dot while its text differs from its file. × closes a tab, and its changes that are not saved. The editor's colors, errors, completions, hovers, and references come from the project's analysis of the tab's file, with the project's errors, such as a read of a table whose data script did not load, and the load's errors, such as a URI that matches no file. F12 or ⌘-click on a table of a chart goes to the statement of the data script that creates it, in its tab, and on `IMPORT MODULE` to the module.
- **Saving**: ⌘S (Ctrl+S), or Save, writes the active tab to its file. A saved data script loads again, with the scripts downstream of it, and the open chart tabs that read a table that changed run again, and so do those that import a module, whose functions can read tables that the chart doesn't name. A saved module loads the whole project again. A chart runs when its tab opens, when it is saved, and on Run, against the project's tables, and its result shows in the result pane, which shows the last result of each tab as the tab shows. A chart that reads a table of a data script that did not load has the error that names the script. A run waits for a load that has not ended, so a chart never reads a project that is partly loaded.
- **Stylesheets**: every chart of the project, in the result pane and in the cells of a table, takes the cascade of the base stylesheet, `std:base.css`, and after it the project's entry stylesheet, `styles/main.css` unless the manifest names another, as an author stylesheet, with the imports of the entry stylesheet in its cascade order. Both read the same `env()` values, such as the panel's `background`, in the light theme and the dark one. A project without an entry stylesheet has the base stylesheet alone. A saved stylesheet loads the stylesheets again, and the charts restyle without running their scripts again: the interactive charts keep their pans, zooms, and selections. A stylesheet's tab colors its text by its tokens, and underlines the errors and warnings of the last load of the stylesheets, its own and those of its imports, such as an unknown attribute or an import that does not load, with the message and help of each on hover. A stylesheet that the entry stylesheet does not reach through its imports has a warning on its first line, since it styles no chart. While a stylesheet's tab is active, the result pane keeps the result of the tab before it, so the chart shows each save of the stylesheet. Completion, Format, ⌘/, the style's indentation, and definitions are for SQL only.

While a project is open, the result pane has no Examples, files dropped on the window are not added, and Run is off in the tab of a data script, which loads when it is saved.

## Limits

- One query in the editor without a project.
- A project's files don't load again when they change on disk, and a stylesheet's errors show only after it is saved.
- The Lifted SQL of a chart that imports a module has the error that the module is not found.
- No Delta tables, no remote files, and no saved sessions yet.
- Charts in table cells have no tooltips while **Interactive charts** is off.
