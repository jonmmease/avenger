# avenger-guides

Visualization guide generation for Avenger (axes, legends, colorbars, attributions).

## Purpose

This crate generates the visual guides that help users interpret data visualizations. It creates scene graph elements for axes, legends, and colorbars using scale information to produce properly positioned and formatted guide components.

## Integration

- **Input**: Uses `avenger-scales::ConfiguredScale` for scale information and data mappings
- **Output**: Generates `avenger-scenegraph` mark hierarchies for rendering
- **Prepared guides**: `Axis`, `Colorbar` and `Legend` are each built once from a scale or entries, a configuration and a text engine, without a length. The constructors check the formats, templates and titles, so the later calls do not fail. Every later call takes a length. An axis sets its scale's range from 0 to that length in the direction that the scale's range had, so the sizes, the drawing and `scale(length)`, which positions the chart's data, agree at every length. A colorbar's or legend's length is its whole length along its side, background included, and `Colorbar::scale(length)` maps the color scale's domain onto the drawn gradient.
- **Parts**: An axis has three parts, `AxisPart::Ticks`, `AxisPart::Labels` and `AxisPart::Title`, which a layout puts in separate slabs, since labels collapse per lane and titles merge per figure. A colorbar and a legend are each one part, with the title at the top: a colorbar's above its gradient, and a legend's above its entries. A colorbar's gradient takes the length that its padding, title and end labels leave, so its end labels stay inside its background. `Axis::extent(part, length)`, `Colorbar::extent(length)` and `Legend::extent(length)` return a `PartExtent`: the thickness, the overhang past each end, and the lengths over which both hold, which is a layout slab's answer. `Axis::part(part, length)` draws an axis part in its slab's frame, where 0 along the length is the slab's start and 0 across it is the part's inner edge, nearest the plot. `Colorbar::marks(length)` and `Legend::marks(length)` draw a whole colorbar or legend with its top left corner at the origin. Each guide's `origin(slot)` gives the origin for a slab's rectangle. A chart draws a guide in each slab that is its own representative.
- **Without a layout**: `Axis::marks(size)` stacks an axis's parts in a plot's frame, and `Axis::grid(size)` draws its grid lines behind the data. `Colorbar::marks(length)` and `Legend::marks(length)` draw a colorbar or legend as they do in a slab.
- **Attributions**: `Attribution` draws a chart's credits, such as its data sources or map tile licenses, in small text above or below the plot. `Attribution::new` takes each credit as Typst markup, such as `"© OpenStreetMap contributors"`, and an `AttributionConfig` with the side, the alignment, the end by default, the separator between credits on a line, the font, the line gap and a `BackgroundStyle`. The credits fill lines in order and break only between credits, so a narrower slab gets more lines and grows thicker. `extent(length)` holds exactly over the lengths that keep the same lines, and a credit longer than the length by itself reports the excess as overhang on the side away from the alignment. `part(length)` draws it in a slab, and `marks(size)` draws it in a plot's bottom corner for a chart without a layout, where its background should have a fill. `content_key()` is equal for attributions with the same credits and configuration, so panels that credit the same sources can share one attribution through a layout's collapse and merge rules.
- **Legend layouts**: `LegendLayout` holds the legend's `GuideSide` and its `LegendWrap`. Lines of entries run along the side. `LegendWrap::Flow` keeps each entry at its own size and breaks a line before an entry that would pass the length. `LegendWrap::Grid` puts the entries in equal cells, filled along the side first, with `columns` fixing the column count, or else as many cells along the side as fit. A legend's `holds` range is exact, so a layout asks again exactly when the entries reflow. Entries that pass the length, as a fixed column count's do beside a short plot, are the end overhang. `Legend::max_content()` is the length with the entries on as few lines as the wrap allows, which a layout asks of a legend's slab as its max-content length. In an avenger-layout slab stack, it sizes the legend's `auto` track, so the legend takes its natural length and a colorbar below it the rest.
- **Labels**: Axes and colorbars format ticks with the text engine's number and datetime providers, which `LabelEngine::with_number_formatting` and `with_datetime_formatting` set. `tick_format` is one pattern for numeric and temporal ticks, in the provider's syntax, such as `",.0f"` or `"%b %d"`. Numbers use the number provider. Dates and timestamps use the datetime provider: timestamps without a timezone as naive datetimes, and timestamps with one as instants, which the provider must show in the scale's timezone. An empty pattern takes the provider's default, which for dates and times is its calendar patterns. Ticks fail to format when the engine lacks their provider. Numeric ticks are formatted together, with the scale's `tick_precision_sharing`: `PrecisionSharing::PerValue` for log, threshold, and quantile scales, and `PrecisionSharing::Shared` for other scales. Axes label the ticks that the scale's `label_ticks` chooses, so log axes label only the minor ticks that fit the requested density. Band and point axes format numeric and temporal categories each on its own, and show other categories, such as strings, as text.
- **Label markup**: `tick_label` is Typst markup for each label, where `#tick` is the tick as `tick_format` formats it, as in `#tick m/s` or `*#tick*`. Numeric ticks with exponent typesetting are Typst math, with or without it.
- **Styling**: `AxisConfig::side` is the axis's `GuideSide`, and `AxisConfig::style` holds colors, fonts, tick count and placement, and title markup. `ColorbarConfig` holds the colorbar's axis configuration, the gradient's thickness, the gap between the gradient and the axis, and its `BackgroundStyle`. `LegendConfig` holds the title, each entry's label and its symbol or line swatch, the layout and a `LegendStyle`, with the title and label fonts, the gaps between entries and the background. Each `Default` is the default look, and `ColorbarConfig::default()` gives a colorbar's labels and title the legends' fonts.
- **Interactions**: `Legend::marks` returns a `GuideLegendOutput`: the drawn group and the scene paths of each entry's group and hit rect. `Colorbar::marks` returns a `ColorbarOutput`: the drawn group and the scene path and bounds of the gradient, which takes the colorbar's hits.
- **Label angles**: Rotated labels align to the end nearest their tick, so that they extend away from the axis, as Vega-Lite aligns them. `label_align` and `label_baseline` set the alignment instead.
- **Nested band axes**: `Axis::nested_band` draws a nested band scale's leaf level as a band axis does and stacks a label row for each outer level outward from it in the labels part, with separators between that level's bands that start at the domain line. Per-level settings hide a level, retitle it, or set its label angle or tick format. Without an explicit title, the axis title joins the visible levels' titles with " / ". A level's numeric and temporal keys are formatted with its tick format, or else the axis's, and explicit labels show as written.
