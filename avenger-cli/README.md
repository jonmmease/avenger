# avenger-cli

`avenger`, the command-line program of avenger-sql projects, for people, scripts, CI, and agents. Each command starts, reads the files, answers, and exits, so a command runs the same way in a terminal, in CI, and in an agent's loop.

```sh
avenger check              # the errors and warnings of the project of the current directory
avenger check --run charts # also run the queries of the charts under charts/
avenger fmt                # format the project's scripts and modules in place
avenger fmt --check        # list the files that need formatting, and change none
avenger lsp                # serve the Language Server Protocol to an editor
avenger render charts/revenue.av.sql -o revenue.png   # draw a chart to PNG, SVG, or PDF
avenger render reports/overview.qmd#fig-sales -o sales.svg --size 640x400 --color-scheme dark
avenger view charts/revenue.av.sql                     # a window that reloads as files change
avenger view charts/revenue.av.sql:12                  # the statement at line 12: a query's rows, or a table
avenger tables                                         # the names of the project's tables
avenger schema datasets.cars                           # the columns, types, and row count of a table
avenger query "FROM datasets.cars"                     # its first rows
avenger query "FROM datasets.cars |> AGGREGATE COUNT(*) AS n GROUP BY Origin" --output csv
avenger query -f charts/revenue.av.sql -o revenue.parquet  # every row of a chart script, to Parquet
avenger charts                                         # the charts, as render and view name them
avenger docs mark_bar.x.scale                          # the reference of a function, a constructor, or a parameter
avenger docs search truncate date                      # search the reference
avenger complete charts/revenue.av.sql:4:21            # the completions at a position
```

## Files and projects

A command takes files and directories, or the current directory without one. A path in a project, under a directory whose `avenger.toml` is the nearest one above it, selects the project's files under the path, by the roles that the manifest gives them: data scripts, chart scripts, modules, and stylesheets. A project loads once, whatever paths select it, as an editor loads it: its data scripts run, so the tables that they create have their schemas when the other files are checked.

Scripts end with `.av.sql` and modules with `.av.sqlm`. A script or a module outside every project, or without a role in its project's manifest, is a loose file: it is checked alone, as a chart script or a module, so it reads no tables of a project, and a read of a table has a help line that says so.

## Quarto documents

A Quarto document (`.qmd`) holds avenger-sql in cells: fenced code blocks whose attributes are `{avenger-sql}`, or `{avenger-sql` and a space or a comma before more attributes, as in `` ```{avenger-sql echo=false} ``. Each cell is a chart script of the project of the document, so it reads the project's tables and imports its modules, and its diagnostics are at their places in the document. A cell of a document outside every project, or of a `.qmd` file among the data, is a loose script. The cell's `--|` option lines are SQL comments to avenger-sql. avenger-sql-project finds the cells, and its README gives the rules of the fences.

## Commands

`avenger check [PATH ...]` reports the diagnostics of the selected files and of the cells of the selected documents: the errors of their syntax and of their analysis, the project's errors, such as a name that two data scripts define, a cycle of data scripts, or a read of a table whose data script would not load, the loader's errors, and the errors of the load of the entry stylesheet in each stylesheet. With `--run`, each chart script and cell without errors also runs its query, which finds errors that appear only when the query runs, such as a cast of a value that fails.

`avenger fmt [PATH ...]` formats the selected scripts and modules in the style of `avenger-sql/STYLE.md`, by the role of each file, and the cells of the selected documents as chart scripts, with the rest of each document as it is, and prints the files that it changed. A statement with a syntax error stays as written. With `--check`, it changes no file, prints the files that formatting would change, and fails when there is one.

`avenger lsp` serves the Language Server Protocol on standard input and standard output, for an editor that starts it. It is the one command that stays running. When the editor opens a script or a module, the server opens its project and loads the project's data scripts in a thread of their own. When that first load comes back, the server publishes the diagnostics of every file of the project, so no file shows errors of tables that the load has not read yet. After it, an edit publishes the diagnostics of the files that it reaches, at once, without waiting for a load: the edited file, the data scripts and the charts that read its tables, and the scripts that import an edited module. A save of a data script or a module loads it again, and so does a change on disk of a data file that a data script reads. A change of the manifest, or a script that appears or goes away, opens the project again. The server watches the files through the editor when the editor offers it, and through its own watch otherwise. A loose file is analyzed alone. In a document, the server answers for positions inside cells and nothing else, so other servers of the document, such as Quarto's, answer for the rest, and a cell of a closed document is a chart script of its project as well, so a rename reaches it.

`avenger docs NAME` prints the reference of avenger-sql as Markdown, from the library that hover and completion read. A name is a function, such as `date_trunc`, or a constructor by the name that a call writes, such as `pin`, with the places that take it and its unique name, such as `domain_pin`. A name of several constructors, such as `title`, prints each, and a unique name, such as `log_scale`, prints its own. A dotted path walks the parameters: `mark_bar.x.scale` is the `scale` parameter of the channel `x(...)`, and each next name is a parameter of the parameter's own constructor, or else a constructor that the parameter takes. `style:NAME` prints a property of the style language, with its values, its initial value, whether it inherits, and the elements that accept it, or a shorthand, or an element, with its parts and its properties. A syntax form, such as `docs "LOAD DATA"`, prints the section of `avenger-sql/SPEC.md` that holds it. `--brief` prints the forms only, and `--examples` the examples only. A name of no entry prints the entries that match it, and fails when nothing does, and so does a path that does not walk.

`avenger docs search WORDS` lists the entries that match every word, best first: a name, a name of another dialect, such as `strftime` for `format_timestamp`, the start of a name or of a part of it, a name a few edits away, a parameter or a word of the summary, then a word of the description, the notes, or the examples. A result that a name of another dialect found names it, as `format_timestamp ... (for strftime)`. `--kind scalar|aggregate|window|table`, `--family googlesql|mark|constructor|transform|composition`, `--returns TYPE`, and `--takes TYPE` keep some of them, and alone they list every entry that they keep. `avenger docs --at PATH:LINE:COLUMN` prints the hover at a position, and `avenger docs --all` prints the whole reference as one Markdown file: the functions, the constructors, the properties, the shorthands, and the elements of the style language, and the spec.

`avenger complete PATH:LINE:COLUMN` prints the completions at a position, as an editor shows them, that start with what the name or the string has before the position, at most `--limit` of them, 50 by default, and `avenger signature PATH:LINE:COLUMN` prints the forms of the call that holds the position, with the form that it takes marked `>`, and the parameter at the position. A position's lines and columns start at 1, and a column counts characters, as the diagnostics print them. A file of a project is analyzed with its project, as `check` loads it, so the columns of its tables complete. A position of a Quarto document is in the cell that holds it, and a loose file is analyzed alone. Nothing at the position fails the command.

`check`, the editor, and every other command suggest a name for a function or a column that a script lacks: `Function not found: date_trunk. Did you mean date_trunc?` from the library, the script's temporary functions, and its modules' functions, and `Unrecognized name: Horsepowr. Did you mean Horsepower?` from the columns in scope, and for the first name of a longer path, such as `ordrs.total`, the range variables. A name of one or two characters suggests nothing.

The server answers hover, completion, signature help, go to definition, references, rename, document symbols, folding ranges, selection ranges, semantic tokens, formatting, and the quick fixes of diagnostics. The strings in a language of their own take no semantic tokens, so an editor's Tree-sitter grammar highlights them by injection: a string of Typst markup, such as a title, which the injection of `tree-sitter-avenger-typst` highlights, a format pattern, of a chart's labels, text, or tooltips or of a function such as `FORMAT_DATE`, and the value of a typed literal, such as `'2024-01-03'` in `DATE '2024-01-03'`. A title of plain syntax is no markup, and keeps its `string` token. The Typst syntax errors of markup are diagnostics. Its positions count UTF-8 bytes when the editor offers them, and UTF-16 code units otherwise.

`avenger render <CHART> -o <OUT>` draws the chart of a chart script, or of a cell of a Quarto document, to PNG, SVG, or PDF, by the extension of `OUT`. It runs the script through its project, or a loose script as a project of one file, and draws its chart with the chart app of `avenger view`, offscreen, with the project's stylesheets and the chart's widgets. A cell is `report.qmd#NUMBER`, the Nth `{avenger-sql}` cell from 1, or `report.qmd#LABEL`, the cell whose leading `--|` lines set `label: LABEL`. A document of one cell needs neither. A script with errors reports them, as `check` does, and renders nothing.

A target at a line, `FILE:LINE` with lines from 1, names the top-level statement that holds the line, in a chart script or in the cell of a document that holds it, the first where two statements start on the line. The script's last query shows the script's value, as the file alone does. An earlier query shows its rows, after the statements before it run, and a statement that makes a table, such as `CREATE TEMP TABLE t AS ...` or `LOAD DATA ... TEMP TABLE t`, shows the table. A line between statements, or on a statement without rows, such as `DECLARE`, is an error that says where the statements are. A data script's statement shows its table as the project's session holds it, the table that other scripts read, so it shows on the last statement that makes the table, and not on a temporary table, which only its script reads. A data script without a line is an error that lists its tables by their lines. A target splits at its last `:` only when digits follow, so a Windows path keeps its drive letter.

A result of one row whose one column holds a chart is that chart. Any other result renders as a table: a header of the column names, then a row for each result row, with each chart in its cell and the other columns as text, and at most `--rows` rows (20 by default), with a note of the rows that it leaves out, or that there are none. A row of text alone is one line of the table's font tall, with less padding than a row of charts, so a result without charts reads as a table of text. `--chart ROW[.COLUMN]` draws one chart of the table alone, with its row from 1 and its column by name, which the only column of charts needs not.

`--size WxH` is the size of a chart, in pixels: of the chart alone, or of each chart of a table. `Wx` and `xH` fix one side. Without it, a chart takes its own width and height, or its natural size, the sizes of its plots and what stands around them, and a table's columns and rows take the largest natural sizes of their charts. `--scale` is the pixel density of PNG, so `--scale 2` doubles its pixels without changing the layout. `--color-scheme light|dark` sets the color scheme that the stylesheets' `prefers-color-scheme` tests and the background that the image draws on, white or `#1e1e1e`, which the stylesheets read as `env(background)`. `--style CSS` adds a stylesheet after the project's, and `--mode NAME`, which repeats, turns on a mode of the chart. The images of a chart, such as the tiles of a map, load with the program's User-Agent through a disk cache in the platform's cache directory, and `render` waits for them for up to `--timeout` seconds (30 by default), then draws without the missing ones and warns.

`avenger render --all -o DIR [PATH]` renders each chart script and cell of the project of `PATH`, or of the current directory, into `DIR`, one image each, in the format of `--format` (`png` by default), named after its path with `/` and `#` as `-`, such as `charts-revenue.av.sql.png` and `reports-overview.qmd-2.png`. A chart that does not render reports its error, and the others render. PNG draws on a GPU through wgpu, and without one, `render` fails and names SVG, which needs none.

`avenger view <CHART>` opens a native window on the result of a chart script, or of a cell, named as `render` names it, and keeps it current. The window shows the result: the chart alone, live, so it pans, zooms, selects, and shows its tooltips, or the table of the result, whose columns and rows resize, whose chart cells open their charts over the table until Back or Escape, and whose cells run their charts' apps with Interactive cells. Two buttons switch between the light and the dark color scheme, which starts from the system's, or from `--color-scheme light|dark`.

The window watches the project's files. A change of the chart's own text runs it again, and so does a change of a data script or a module that it reads, through a table that changed or an import, or of a data file that such a data script reads. A change of a stylesheet restyles the chart without running it, a change of the manifest opens the project again, and a change of another chart does nothing. A chart that runs again keeps its pans, zooms, and selections. A run that fails keeps the result before, and its errors show in a bar at the bottom of the window and on standard error. A cell named by its label keeps its label as its document changes around it.

The commands of a project's data go from the names of its tables, to the columns of the tables that a chart reads, to their rows. `avenger tables` lists the names of the tables and the views that the project's data scripts register, each with its data script. A temporary table belongs to its script and is not listed. `avenger schema TABLE...` prints the columns of the tables that it names, with their types as GoogleSQL names, such as `INT64` and `STRING`, their row counts, and their data scripts, and without a name, of every table. A table is named as a data script names it, such as `datasets.cars`, or by its name alone in the default schema, and a table of another schema by its name alone suggests its path, and a name a few edits away the closest table. A row count reads the table, and a view's count runs its query. `avenger query "FROM datasets.cars"` prints the first rows. A data script that does not load reports its errors on standard error, as `check` reports them, and fails `tables` and `schema` without a name, and its tables are missing. The commands work in the project of the current directory, or of `--project DIR`.

`avenger query <SQL>` runs a query in the project's session, as a chart script of the project runs, with the tables of its data scripts and its modules, and prints its rows. `-f FILE` runs a file in place of `SQL`: a chart script or a cell, named as `render` names it, or another file of a project, which runs in its project. The rows print as a table by default, or by `--output`: `csv`, `json` (an array of objects), `parquet`, or `arrow` (an Arrow IPC file). `-o FILE` writes them to a file, in the format of its extension unless `--output` names one. Parquet and Arrow go to a file or a pipe, and not to a terminal. `--limit N` keeps the first `N` rows, and `--limit all` every row. Without it, rows that print keep the first 10, and rows that `-o` writes keep every row. A limit that cuts rows off says so on standard error. A chart prints as `<chart>`, except in Parquet and Arrow, which keep its bytes, as `render` reads them. The rows collect before anything prints, so a query that fails prints no rows, and its errors print on standard error, as `check` prints them, at their places in the query: `<query>:LINE:COLUMN` for a query of the command line. `--explain` prints DataFusion's logical and physical plans in place of the rows.

`avenger charts` lists the chart scripts of the project and the cells of its documents, by the names that `render` and `view` take, a cell by its label when it has one, each with the columns of charts of its result. The queries plan and do not run. A query that does not plan lists its error and fails the command.

## Output

Results go to standard output, and the counts of errors and warnings and the errors that keep a command from running go to standard error. Text output has colors on a terminal, and `NO_COLOR` turns them off. A diagnostic prints as `path:line:column: severity: message`, with the line of the text and a marker under its range, and its help after `= help:`. Paths are relative to the current directory when they are under it. Lines and columns start at 1, and a column counts characters. An error of a whole file, such as the failure of a chart's query, has no line and column, and the same error of a cell is at the cell's first line.

`--json` prints one JSON object, whose shape changes only with its `version` field. `check` prints `{"version": 1, "diagnostics": [...]}`, where each diagnostic has `path`, `range` (with `start` and `end` lines and columns and the `bytes` of the range in the file, or `null`), `severity` (`error` or `warning`), `message`, `help`, and `source` (`syntax`, `analysis`, `project`, `loader`, `typst`, `style`, or `run`). `fmt` prints `{"version": 1, "formatted": [...]}`, or with `--check`, `{"version": 1, "unformatted": [...]}`. `render` prints `{"version": 1, "written": [...]}`, the images that it wrote, and its errors as `check` prints them, with the source `render` for an error of the result or of a picked chart. `tables` prints `{"version": 1, "tables": [...], "diagnostics": [...]}`, where each table has `name`, `path` (its names), and `script`, and `schema` prints the same with each table's `rows`, `error` (of a row count that fails, or `null`), and `columns`, each with `name` and `type`. `query` prints `{"version": 1, "columns": [...], "rows": [...], "more": false}`, where each column has `name`, `type`, and `chart`, each row is an object, and `more` says whether the limit cut rows off, or with `--explain`, `{"version": 1, "plans": [...]}`, each with `type` and `plan`. `--json` and `--output` both choose what `query` prints, so they don't go together, except with `-o`, where `--json` prints `{"version": 1, "written": [...]}`. A query that fails prints its errors as `check` prints them. `docs` prints `{"version": 1, "entries": [...]}`, where each has `kind`, `name`, and `markdown`, or for a search, `{"version": 1, "results": [...]}`, where each has `name`, `kind`, `summary`, and `alias`, the name of another dialect that found it, or `null`. `complete` prints `{"version": 1, "range": {...}, "items": [...], "more": false}`, where each item has `label`, `kind`, `detail`, and `insert`, and `signature` prints `{"version": 1, "signatures": [...]}`, where each has `label`, `active`, `documentation`, `parameter`, and `parameter_documentation`. `charts` prints `{"version": 1, "charts": [...]}`, where each has `target`, `cell` and `label` (or `null`), `charts`, the names of its columns of charts, and `error`.

## Exit status

| Status | When |
|---|---|
| 0 | The command succeeded: no errors, or no file that needs formatting. Warnings do not change the status. |
| 1 | `check` found errors, `fmt --check` found a file that needs formatting, a chart or a query failed, a data script did not load for `tables`, a chart did not plan for `charts`, nothing matched for `docs`, or nothing was at the position for `docs --at`, `complete`, or `signature`. |
| 2 | The command could not run: a usage error, a path that does not exist, a file that is not a script, a module, or a stylesheet, a directory outside every project for a command of a project's data, a table that the project lacks, or a project whose manifest cannot be read. |

No command prompts.
